# Контекст проекта

Это бот Яндекс Мессенджера для двух независимых задач:

- выгрузка цен конкурентов СБИС и Контур.Экстерн в Excel и SQLite;
- обогащение ИНН из `.txt`/`.xlsx` через DaData.

## Структура

```text
main.py                  единая точка запуска (PM2): бот, планировщик, очередь панели, Flask-админка
config/                  config.toml (секреты), chats.toml, config.modules.example.toml
yandexbot/
  bot.py                 polling чата, команды, очередь заданий панели; CLI: python -m yandexbot.bot
  core/                  config.py (пути, конфиг, лог), access.py, state.py, utils.py, module_registry.py
  messenger/             ym_api.py (Bot API Яндекс Мессенджера), seen_log.py
  admin/                 server.py (Flask-маршруты), status.py (данные для страниц), store.py (SQLite admin.db),
                         templates/ (Jinja, автоэкранирование), static/admin.css
  modules/               prices.py (1СО СБИС/Контур), epd_prices.py (ЭПД), enrich.py (DaData), archives.py (архивы исходников)
tests/                   unit-тесты без сети
scripts/                 ручные живые прогоны: epd_prices_live_test.py, kontur_live_test.py, seen_ids.py
stat/                    runtime-данные: prices.db, admin.db, лог, отчёты (путь не менять); архивы исходников — stat/archive/
```

Импорты — абсолютные от пакета: `from yandexbot.core import config`, `from yandexbot.modules import prices`. Команды запускаются из корня проекта. `config.py` ищет `config.toml` и `chats.toml` сначала в `config/`, затем в корне (старая раскладка на сервере до переноса файлов).

## Архивы исходников

По первой успешной выгрузке обоих поставщиков за календарный месяц сохраняется ZIP с Excel и исходниками в `stat/archive/` (`yandexbot/modules/archives.py`). Для 1СО это `prices_sources_ГГГГММ.zip`, для ЭПД — `epd_sources_ГГГГММ.zip`. Последующие выгрузки обновляют Excel и историю цен по обычным правилам. Прогон ЭПД из терминала может сохранить месячный ZIP при `--save-db`, выборе обоих источников и создании Excel. Старые ZIP остаются доступными. Архивы из `stat/` переносятся в `stat/archive/` при старте.
В чаты архивы не отправляются (рассылка архивов удалена): их скачивают в панели → «Отчёты», вместе со старыми `kontur_sources_*.zip` (только Контур). Задания `archives/send`, оставшиеся в очереди, помечаются `failed`.

## Админ-панель

Flask в потоке процесса `main.py`, порт 5001 (`--admin-port`). Страницы — Jinja-шаблоны, HTML в Python не собирать. CSRF-токен выдаётся в `before_request` и проверяется на всех POST, включая вход. Задания «Запусков» только ставятся в `module_runs`; выполняет их `bot._run_admin_queue()` под теми же `prices_lock`/`epd_prices_lock`, что и команды чата; зависшие `running` при старте помечаются `failed`. Статус циклов бота — `state.heartbeat`. Отчёты отдаются только из списка файлов `stat/` (`status.report_path`). Чаты рассылки выбираются отдельно для «Цен 1СО» и «Цен ЭПД» (`broadcast_chats` в настройках модуля, `access.module_chat_ids/module_targets`); `prices.run`/`epd_prices.run` с `target=None` шлют в чаты своего модуля. Пока модуль не сохранён или выбранные чаты удалены — все чаты с флагом broadcast. Лимит DaData — одно значение в настройках модуля enrich, его меняют и панель, и `/лимиты`. Доступы по логину (`access.is_admin/is_employee`) берутся только из `access_logins` в admin.db: `[access]` из config.toml переносится туда один раз (`import_config_access`, флаг в таблице `meta`) и дальше прав не выдаёт.

## Конфигурация и состояние

`config/config.toml` содержит токены и идентификаторы: не выводить его содержимое, не добавлять в тесты и не коммитить секреты. `stat/` содержит рабочую БД, логи, offset polling и созданные отчёты; это runtime-данные, а не исходники.

Список чатов, сохранённый в панели, хранится в `stat/admin.db`. После первого сохранения панель применяет его и при пустом списке. Старый `chats.toml` и резервные получатели из `config.toml` работают до сохранения списка в панели. При замене исходников сохраняйте серверный каталог `stat/`.

## Выгрузка цен

`/цены` запускает `prices.run("both")` без общего таймаута. Одновременные выгрузки защищены `prices_lock` из `yandexbot/core/state.py`.

СБИС берётся из регионального JSON-каталога. `SBIS_EXCEL_GROUPS` связывает номенклатуру, ключ истории SQLite и колонку Excel. «Выгодный старт» выгружается отдельно как тариф для новых клиентов.

Контур парсится Playwright в `parse_kontur()` по официальным файлам со страницы `price-download/<id>`. Таблицы части 2 распознаются по заголовкам. Для тарифов малого бизнеса `kontur_biz_form` строит форму из категории клиента, системы налогообложения и признака НДС. Для «Филиального» цены разбиваются по числу обособленных подразделений и системе налогообложения. «Общий» и «Общий +» берутся из части 2. «ОБ Универсальный» и «ОБ Все включено» берутся из отдельного PDF по ценовой зоне региона, включая пакеты дополнительных абонентов. Разбор старого «Общего Лайт» сохранён для прежних прайсов.

«ИП без сотрудников» и «Налоговый представитель» публикуются в PDF. Прежние DOCX также поддерживаются. Для НП выгружаются Лайт/Базовый/Плюс по регионам и Премиум по РФ за 12 мес., а также цены за документ по регрессивной зоне (у зон 4 и 10 свои интервалы). Ключи истории — `НП | <тариф>` и `НП за документ | <интервал>`. «Нулевая отчетность» и «Кадровые отчеты» берутся из общего PDF. Ручной запуск скачивает все файлы с ценами, плановый сохраняет полный комплект. Новые тарифы и формы перечисляются в итоговом сообщении (`compare_prices` → `new_tariffs`). Не подбирать и не использовать замену снятому с публикации `CalculateBillingPrice`.

Если Контур отвечает 403, сначала зафиксировать HTTP-статус, title страницы и URL без вывода cookies/заголовков авторизации. Это внешнее ограничение доступа, а не повод обходить защиту сайта.

## Выгрузка цен ЭПД

`/эпд-цены` запускает `yandexbot/modules/epd_prices.run()`. СБИС берётся из JSON-API прайса Saby (номенклатуры `ETRN_*` — пакеты, `ETRNPOST*` — постоплата, дополнения TMS/путевые листы/выездные сотрудники — словарь `SBIS_ADDONS`), при сбое API — из HTML страницы тарифов по `nomenclaturecode`. Контур берётся из официального PDF: таблица 1 — пакеты, таблицы 2–14 — дополнения (цена с НДС); страница `kontur.ru/logistika/price` служит сверкой и резервом для пакетов. Расхождения и переход на резервный источник попадают в итоговое сообщение. Сообщение сравнивает выгрузку с прошлой из `epd_prices` (`price_changes`/`format_changes`): первая строка — «ЕСТЬ ИЗМЕНЕНИЯ ЦЕН» или «цены без изменений», ниже по поставщику 📈/📉 было → стало, 🆕 новые, ➖ пропавшие. Если общих позиций нет (сменился формат названий) — «сравнивать не с чем»; массовое исчезновение позиций считается неполным ответом источника. В Excel: жёлтым — изменённые (примечание «Было: …»), зелёным — новые.

Плановый запуск ЭПД настраивается в панели («Цены ЭПД»: интервал в днях и время, по умолчанию выключен); `epd_prices.scheduler_loop()` работает в `main.py`, итог уходит в чаты с рассылкой, время прошлого запуска — `stat/epd_last_run.json`. Расписание 1СО и ЭПД считается общим `yandexbot/core/schedule.py`: «через N календарных дней, не раньше ЧЧ:ММ», проверка раз в 5 минут.

Переключатель «Отправлять только при изменении цен» (`auto.only_changes`, по умолчанию включён) действует на плановые запуски 1СО и ЭПД. При совпадении цен Excel и история в БД сохраняются, ZIP создаётся по месячному правилу, в лог пишется причина пропуска рассылки. Всегда отправляются: ошибка источника, первая выгрузка/смена формата, пропавшие позиции (`prices.compare_prices` → `missing`, для ЭПД — `removed`). Команды чата и «Запуски» отвечают всегда. Проверка — `prices.has_news` и `epd_prices.has_news`. История помечается `run_kind` (`auto`/`manual`, колонка добавляется при подключении к БД): плановая выгрузка сравнивается только с прошлой плановой (или старой строкой без отметки), ручная — с любой.

Тестовый прогон без бота (ничего не отправляет, БД не меняет, Excel кладёт в `stat/`):

```powershell
.\venv\Scripts\python.exe scripts\epd_prices_live_test.py [--source sbis|kontur|both] [--save-db] [--no-excel] [--out файл.xlsx]
```

## Проверка изменений

Для изменения логики Контур добавляйте быстрый тест в `tests/test_prices.py` или `tests/test_kontur_region.py`; их fake-страницы позволяют проверять запросы без сети. Перед сдачей запускайте:

```powershell
$env:PYTHONUTF8='1'
.\venv\Scripts\python.exe -m unittest discover -s tests -t .
.\venv\Scripts\python.exe -m compileall -q main.py yandexbot scripts
```

Живой прогон Playwright выполняйте только на одном тестовом регионе, с ограниченным числом запросов и без публикации ответов, содержащих секреты. Для изменения поведения чата также проверяйте `python main.py --check` с имеющейся конфигурацией.

## Стиль

Код и комментарии преимущественно на русском. Сохраняйте UTF-8 без BOM; при работе с текстовыми файлами явно задавайте UTF-8. Ошибки одного внешнего источника должны давать понятное сообщение и не маскироваться успешной выгрузкой другого источника.
