# Документация предметной области

Правила использования документации предметной области при исследовании кодовой базы.

## Перед началом работы

Прочитайте относящиеся к задаче материалы:

- корневой `CONTEXT.md`;
- `CONTEXT-MAP.md`, если он существует: он указывает на контекстные `CONTEXT.md`;
- ADR в `docs/adr/`, затрагивающие изменяемую область.

Если этих файлов нет, продолжайте работу без предупреждения. Навык моделирования предметной области создаёт их только когда действительно появляются согласованные термины или решения.

## Структура

Это single-context проект:

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── исходные файлы проекта
```

## Терминология и ADR

Используйте термины из `CONTEXT.md` в названиях задач, предложениях по рефакторингу, гипотезах и тестах. Если нужного понятия там нет, проверьте, не является ли это неиспользуемым синонимом; при реальном пробеле отметьте его для моделирования предметной области.

Если предлагаемое изменение противоречит ADR, явно укажите это и причину возможного пересмотра решения.
