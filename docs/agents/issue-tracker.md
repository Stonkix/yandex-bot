# Трекер задач: локальные Markdown-файлы

Задачи и спецификации проекта хранятся как Markdown-файлы в `.scratch/`.

## Соглашения

- Одна задача верхнего уровня — один каталог: `.scratch/<feature-slug>/`.
- Спецификация располагается в `.scratch/<feature-slug>/spec.md`.
- Тикеты реализации хранятся по одному в `.scratch/<feature-slug>/issues/<NN>-<slug>.md`; нумерация начинается с `01`.
- Статус тикета указывается строкой `Status:` в начале файла.
- История обсуждения дописывается внизу файла под заголовком `## Comments`.

## Публикация и чтение задач

Если навык просит опубликовать задачу в трекере, создайте нужный файл в `.scratch/<feature-slug>/` вместе с отсутствующими каталогами.

Если навык просит получить тикет, прочитайте файл по переданному пути. Обычно пользователь указывает путь либо номер тикета.

## Навигация по задачам

- Карта работы: `.scratch/<effort>/map.md`.
- Дочерний тикет: `.scratch/<effort>/issues/NN-<slug>.md`.
- В тикете указываются `Type:` (`research`, `prototype`, `grilling` или `task`) и `Status:` (`claimed` или `resolved`).
- Зависимости фиксируются строкой `Blocked by: NN, NN`. Тикет разблокирован, когда все перечисленные тикеты имеют статус `resolved`.
- Перед началом работы установите `Status: claimed` и сохраните файл.
- По завершении добавьте ответ под `## Answer`, установите `Status: resolved` и зафиксируйте ссылку на контекст в разделе решений `map.md`.
